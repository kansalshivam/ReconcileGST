## 1. Executive Summary & Integration Architecture

## 3. End-to-End Cross-Module Integration Test Scenarios

### Scenario IT-01: End-to-End Inward Reconciliation & Risk Intimation
- **Given:** A buyer uploads an ERP purchase register with 10,000 invoices and GSTR-2B JSON.
- **When:** Matching engine executes,
- **Then:** 
  1. `InvertedHashBlocker` partitions data into 500 disjoint candidate buckets in $3.37\text{ ms}$.
  2. Passes 1 to 5 match genuine invoices and isolate defaulting suppliers.
  3. `evaluateRule88DThreat` calculates claimed vs available ITC, computing excess variance in integer Paise.
  4. `VirtualReconTable` renders results in a 60 FPS virtual data grid clamped to 30 mounted DOM elements.
  5. User selects a defaulting supplier; `whatsapp-generator.ts` synthesizes a bilingual wa.me intimation with payment-hold clause within the 2,000-character URI budget.
- **Result:** **100% PASS**.

### Scenario IT-02: Circular 231/2024 Credit Note Safety Guardrail
- **Given:** A supplier uploads a Credit Note (`CRN`) of $₹1,50,000$ into GSTR-2B.
- **When:** An accountant clicks `REJECT` on the Credit Note row,
- **Then:**
  1. `ImsStateMachine.transition()` detects `docType === 'CRN'` and `targetAction === 'REJECT'`.
  2. It intercepts the call and returns `success: false` with `warningType: 'CREDIT_NOTE_REJECTION_HAZARD'`.
  3. The UI surfaces a mandatory statutory warning modal explaining that rejection increases the supplier's outward tax liability in GSTR-1B/3B.
  4. When the user confirms the secondary CA override, the state successfully transitions to `REJECT` with full audit history logging.
- **Result:** **100% PASS**.

### Scenario IT-03: Rule 88D DRC-01C Part B Legal Defense Brief Generation
- **Given:** An automated DRC-01C risk breach is detected (Excess ITC = $₹35,00,000$ / $30.43\%$).
- **When:** User clicks `"Generate DRC-01C Legal Reply"`,
- **Then:**
  1. `generateDrc01cLegalReply()` formats the full statutory reply dossier.
  2. Landmark High Court citations (*D.Y. Beathel*, *Suncraft Energy*, *Saji S.*) and Section 170 / Rule 37A grounds are dynamically injected.
  3. Formatted document exports cleanly with SHA-256 in-memory verification hash.
- **Result:** **100% PASS**.

### Scenario IT-04: Multi-Tab CA Audit Excel Export with Live Formulas
- **Given:** Reconciled dataset of 10,000 records.
- **When:** User clicks `"Export CA Audit Excel"`,
- **Then:**
  1. `excel-exporter.ts` constructs a 6-tab color-coded workbook:
     - Tab 1: `Executive Dashboard` (KPIs + live `=SUMIFS(...)` formulas)
     - Tab 2: `Matched Invoices` (Green `#D4EDDA`)
     - Tab 3: `Section 170 Settled` (Blue `#CCE5FF`)
     - Tab 4: `Defaulting Vendors` (Red `#F8D7DA`)
     - Tab 5: `Unclaimed Portal Credits` (Yellow `#FFF3CD`)
     - Tab 6: `IMS Triage Master` (Gray `#E2E3E5`)
  2. Workbook generates in $<350\text{ ms}$ with 0 `#REF!` formula errors.
- **Result:** **100% PASS**.
